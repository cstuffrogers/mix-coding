多平台目录适配方案
目标
让本项目同时支持 Claude Code、opencode、Codex、ZCode 四个平台,每个平台有独立 .xxx/ 配置目录(类似 Trae 的 .trae/),且完全不破坏现有 Claude Code 使用。

核心判断(基于源码勘察)
引擎和 Claude 的耦合只有两类,都是"加法不破坏原值"的改造:

环境变量门控:54 处 process.env.CLAUDECODE === '1',语义是"当前是否在对话型 agent 宿主里"
路径写死:.claude/ 目录在引擎里被引用,分两类:
平台共享资源(引擎读):scenes/ skills/ rules/ memory/ plugins/ brand-specs/
运行产物(引擎写,各平台共用):logs/ reviews/ designs/ reports/ previews/ decks/ animations/ prototypes/ infographics/ notifications.log
目录结构设计
采用「共享资源留 .claude/ + 各平台并行 .xxx/」方案(你选的"多平台都能同时用"):

为什么共享资源留 .claude/ 而不是抽到 .mix/:引擎现状已有 40+ 处 join(x, '.claude', ...) 引用,改动成本高且易错。共享资源放原处,各平台通过软链或直接路径访问,改动最小、风险最低。各平台的专属配置(commands 格式、MCP 配置文件名、入口指令)才独立成目录。

改造内容
第 1 步:引擎加平台识别层(改 2 个文件,新增 1 个)
新增 claude-scene/src/lib/platform.js(~30 行):


javascript
import { existsSync } from 'fs';
import { join } from 'path';

// 当前宿主平台识别
export function getHostPlatform() {
  if (process.env.CLAUDECODE === '1') return 'claude';
  if (process.env.OPENCODE === '1') return 'opencode';
  if (process.env.CODEX === '1') return 'codex';
  if (process.env.ZCODE === '1') return 'zcode';
  return 'cli';  // 纯 CLI 模式(无宿主)
}

// 是否在对话型 agent 宿主里(替代所有 CLAUDECODE 判断)
export function isConversationMode() {
  return getHostPlatform() !== 'cli';
}

// 各平台专属配置目录名
const PLATFORM_DIRS = {
  claude: '.claude',
  opencode: '.opencode',
  codex: '.codex',
  zcode: '.zcode',
};

// 共享资源目录(各平台都从这里读 scenes/skills/rules/memory)
// 保持 .claude/ 为单一数据源,避免多份漂移
export const SHARED_RESOURCE_DIR = '.claude';
改 claude-scene/src/lib/paths.js(2 行,语义不变):

现有 SCENES_DIR/MEMORY_DIR 继续指向 .claude/(共享资源留在原处)
只补一个注释说明"此为共享资源,各平台共用"
第 2 步:替换 54 处 CLAUDECODE 判断(改 4 个文件)
机械替换 process.env.CLAUDECODE === '1' → isConversationMode(),对 Claude 行为零变化(因为 Claude 时 CLAUDECODE=1 → isConversationMode() 仍返回 true):

文件	处数
claude-scene/src/lib/conditions.js	21(行 51-113)
claude-scene/src/actions.js	30(行 445-528)
claude-scene/src/handlers/review.js	2(行 286, 316)
claude-scene/src/handlers/flow-control.js	1(行 167)
每个文件顶部加 import { isConversationMode } from '../lib/platform.js';。

为什么不影响 Claude:isConversationMode() 对 CLAUDECODE=1 返回 true,与原判断完全等价。这是 OR 链扩展,不是替换。

第 3 步:创建 opencode 目录与配置
.opencode/AGENTS.md:软链 ../CLAUDE.md(或副本,但软链避免漂移)。 .opencode/opencode.json:从 .claude/mcp.json 转换 MCP 配置(opencode 用 mcpServers 字段,stdio schema 一致,基本直接复用)。 .opencode/commands/:opencode 命令是 markdown 文件,格式接近 Claude,可直接软链 .claude/commands/ 或逐个适配 frontmatter。

第 4 步:创建 Codex 目录与配置
.codex/AGENTS.md:软链 ../CLAUDE.md(Codex 用 AGENTS.md 作项目指令)。 .codex/mcp/:Codex MCP 配置(stdio,从 .claude/mcp.json 转换)。 .codex/prompts/:Codex 无 /command 斜杠机制,把 .claude/commands/*.md 转成 prompts/profiles。 注:Codex 的 commands 适配需要权衡(转为 prompts 或留在 AGENTS.md 指令块),先做 MCP + AGENTS.md 验证链路。

第 5 步:ZCode 目录(待实测)
ZCode 的扩展点(commands/agents/hooks/MCP)官方文档不足,需实测其配置目录。先建 .zcode/ 占位 + AGENTS.md,后续按实测结果填充。这一步可能需要你提供 ZCode 的配置规范,或我实测后补充。

第 6 步:根目录 AGENTS.md + 文档
根 AGENTS.md 软链 CLAUDE.md(opencode/Codex 入口)
更新 CLAUDE.md 末尾加一节"多平台支持说明",记录各平台 env 变量约定(OPENCODE=1/CODEX=1/ZCODE=1)和目录用途
新增 MULTIPLATFORM.md(或并入 README)说明各平台如何配置 env 变量进入对话模式
验证方法(确保不破坏 Claude)
Claude 回归:在 Claude Code 里跑 node claude-scene/src/index.js start check --auto,对比改造前后输出一致
CLI 模式不变:无 env 变量时 getHostPlatform() 返回 'cli',所有 MCP/skill 步骤照旧跳过
opencode 链路:设 OPENCODE=1 跑同一场景,验证 MCP 步骤进入"对话模式"分支
跑 npm run scan:all:确认引擎自检通过
改动量与风险
项目	量	风险
引擎代码	4 文件 54 处机械替换 + 1 新文件(~30 行)	极低(等价替换,Claude 行为不变)
新增目录	.opencode/ .codex/ .zcode/ 各 2-4 文件	零(新增不碰旧文件)
软链	AGENTS.md → CLAUDE.md 等	低(Windows 软链需开发者模式,备选副本)
共享资源路径	不改(留 .claude/)	零
最大风险点:Windows 上软链需要管理员/开发者模式。备选方案是用副本 + 在 CLAUDE.md 顶部注明"修改请同步 AGENTS.md",或用 git hook/脚本保持同步。这点在实施时确认你的环境偏好。

不做的事
不重构引擎把 .claude/ 抽成 .mix/(改动 40+ 处路径,收益不抵风险)
不改变 scenes/skills/memory 的存储位置(共享数据单一源)
不动 .claude/settings.json / settings.local.json(Claude 专属 hooks/permissions)
不在引擎里写死任何平台名(全部走 getHostPlatform() 动态判断)
