## 诚实评估：硬阻断 vs reviewed check 的关键区分

### 硬阻断证明了什么（确实成立）
- **机械强制层成立**：`process.exit(1)` 不是 console.log 警告——agent 无法输出后忽略。跨过 v3「软约束（可忽略）」门槛，进入「机械硬约束（不可忽略）」。
- **场景级 opt-out 精确**：仅 `plan-ceo-review` 1 个场景声明 `allow_no_verify=true`（策略审查生成报告，天然无验证），其余 26 场景不豁免。opt-out 显式、可审计。
- **单测护栏 + 不误阻断**：11 单测覆盖 opt-out 豁免与 false 仍阻断；27 场景全跑 missingVerify=0，硬门禁只在 agent 跳过验证时触发。

### 硬阻断不等于什么（关键边界）
- **硬门禁只验证「verify 步骤存在于 completedSteps」**（`hasVerify` 布尔值）。它检查「agent 跑过某个 lint/test/verify/build 动作」，**不检查该动作结果是否通过**，**不检查该结果是否被 reviewed relevant check 审视并确认**。
- **`withReviewedRelevantCheck` 仍为 0**：DELIVERY EVIDENCE「No bounded evidence observed」未变，`reviewedCandidateCount=0`、`comparableModelOutcomeEvidence=false` 未变。无证据表明 verify 结果被绑定到一次 reviewed 的闭环。
- **finding #2 状态判定**：硬门禁成立了「reviewed-check 闭环的必要条件」（必须有 verify 步骤），未成立「充分条件」（verify 结果被 reviewed）。故 **Pending（无机械强制）→ Partial（机械硬门禁成立，reviewed-check 闭环仍缺）**，未达 Verified。

### 对评分的影响
- **Reliable Delivery 从 not observed → observed（保守）**：跨过 observed 门槛，但因属「verify-presence 硬门禁」而非「reviewed-check-result 绑定」类型，给保守 observed 分数，不因硬阻断全量计入而跃升。
- **Loop Effectiveness 严格口径**：仍需「可比后续任务结果」。v4 证据 `comparableModelOutcomeEvidence=false`、`reviewedCandidateCount=0`、`closedEpisodeCount=0` 均未变。硬门禁强化 Reliable Delivery 机械强制层，但不产生「可比后续任务结果」窗口。故 Loop 仅 +2（69→71），不跃升。

## 整体结论（相比第三轮 v3）

- **Asset Health 74 → 79（+5）**：finding #2 从 Pending→Partial（机械硬门禁 `process.exit(1)` + 场景级 opt-out + 11 单测 + 27 场景精确豁免），Pending 计数清零（1→0）。这是本轮改善主因。
- **Loop Effectiveness 69 → 71（+2）**：Reliable Delivery 首次 observed 间接强化 loop 的「交付前必验证」闭环强度，但严格口径仍需「可比后续任务结果」，小幅上升不跃升。
- **5 维度**：Reliable Delivery 从 not observed → observed（保守，verify-presence 硬门禁类型，非 reviewed-check-result 绑定类型）；Change Validation 三重门禁延续；其余 3 维度与 v3 基本一致。
- **最大剩余杠杆**：把硬门禁从「verify 步骤存在」升级为「绑定到 reviewed relevant check 结果」，关闭 `withReviewedRelevantCheck=0`；为 Learning Capture 建立第二个可比观察窗口。
- **诚实边界**：本轮 #14 是硬约束质变（高权重），跨过 Reliable Delivery 的 observed 门槛与 finding #2 的 Partial 门槛。但 better-harness 对「机械强制 verify 存在」与「reviewed check 结果闭环」有严格区分——硬门禁成立前者，未成立后者（`withReviewedRelevantCheck=0` 未变）。未修项（±50-line 边界、Learning Capture 时间窗口、19 处复杂度豁免、#4 post-edit 行为未验证）如实保留。
