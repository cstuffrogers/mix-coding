- **#12 warning 清零（中权重，洁癖型）**：5 个占位 handler `_` 前缀 + import-x disable。让 claude-scene lint 0/0。本身是「洁癖修复」，但配合 #13 的 `--max-warnings 0` 才有意义——否则 warning 阻断会卡死提交。权重中。
- **#13 复杂度机械强制（高权重，质变）**：`no-unused-vars: error` + `cognitive-complexity: ["error",15]` + `--max-warnings 0`。这是 Change Validation 机械强制层的**第二次质变**：v2 是「error 阻断」，v3 是「error+warning+复杂度三重阻断」。新代码超复杂度阈值即 error，warning 也阻断提交。高权重。
- **#14 acceptance-check（中权重，中约束）**：classifyAction+checkAcceptance+9 单测+startScene 收尾调用。这是 Reliable Delivery 的**首次结构化护栏**——从「纯 console.log 提示」升级到「有条件结构化警告 + 单测护栏」。但**仍是软约束**（警告不 exit 阻断），agent 可输出后忽略。诚实评估：警告 ≠ reviewed-check 闭环，`withReviewedRelevantCheck` 仍为 0。better-harness 对软约束保守，Reliable Delivery 维度**未跨过证据门槛**，仍 not observed，但缺口从「无结构化护栏」收窄到「有中约束护栏但未硬绑定」。
- **Loop Effectiveness 严格口径**：仍需「可比后续任务结果」。本轮 4 项修复是代码层证据，强化了 Change Validation 的「机械强制」子项，但尚无「可比后续任务结果」窗口（`comparableModelOutcomeEvidence=false`、`reviewedCandidateCount=0` 未变）。故 Loop Effectiveness 仅 +3，不跃升。
