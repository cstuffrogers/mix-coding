# /check — 引擎自检

7 步工作流：**Pre-flight 记忆召回 → 检测（handler 验证 / 冒烟测试 / 门禁实现）→ 报告**

> 这一步只做检测，不自动改引擎源码。
> 早先有两个「自愈」步骤（补 action message 表、补 gate flag 映射），都是把猜出来的名字
> 直接写进数据文件再盖一个 `Auto-generated by /check` 的戳：文案表让拼错的 action 名躲过
> 死动作检查，gate flag 映射把 `depCruiserPassed` 猜成 `dep_cruiser`（真名是 `depcruise`）。
> 猜出来的映射没人验证，还每次运行都把仓库工作区弄脏 —— 所以两个自愈步骤都删了，
> 缺什么由报告点名，由人决定怎么接。

## Usage

```text
/check                    # 交互式自检
/check --auto             # 自动模式（只跳过交互，检测逻辑不变）
```

## 执行流程

### Phase 0: Pre-flight

1. **recall** (`step 0.5`) — 注入历史自检上下文

### Phase 1: 检测

2. **verify-handlers** (`step 1`) — handler 完整性验证：inline stubs / CE stubs / pseudo-stubs / 工具健康 / orphan actions
3. **check-smoke** (`step 2`) — 运行 Vitest 冒烟测试（dead action / handler smoke / await-safeExec / scene JSON）
4. **check-gate-flags** (`step 4`) — 交叉对比场景声明的门禁名（`checkGate.checks[]` / `checkGate.gate`）与引擎实现，点名引擎不认识的门禁

### Phase 2: 报告

5. **self-check-report** (`step 7`) — 生成结构化自检报告（冒烟三态 + 门禁实现情况）
6. **remember** (`step 8`) — 保存自检结果到记忆
7. **consolidate** + **notify** (`step 9-10`) — 记忆整理 + 通知

### 检测原则

- 「没跑」「没读到」不算通过：冒烟测试三态（pass / fail / 未执行），扫描范围为空一律 warn
- 门禁检查只问能证伪的事：场景写了某个门禁名，引擎认不认识
- 发现的问题只点名，不自动往引擎源码里写猜测

### CLI 模式回退

在 CLI 模式（非对话）下，`recall` 和 `invokeSkill` 步骤自动跳过。检测和报告步骤正常执行。
